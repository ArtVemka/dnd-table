# 📋 Саммари: DnD App — P2P через iroh

## 🎯 Цель
Довести P2P-интеграцию до рабочего состояния: игроки подключаются к столу ДМа через iroh, игровые события (socket.io) идут поверх iroh QUIC-стримов.

## ✅ Что уже сделано

### 1. Разобран iroh API (napi-биндинги)
- `Endpoint.builder() + RelayMode.disabled()` + прямой коннект по `serverAddr` — **работает** (echo-тест прошёл).
- Relay-режим: `online()` в песочнице виснет (нет доступа к публичным relay), но **коннект без ожидания `online()` работает** (идёт по прямому IP `192.168.1.7`, `isIp:true`).
- Bi-streams: `openBi/acceptBi`, `SendStream.write`, `RecvStream.read`.

### 2. Реализован P2P-туннель (socket.io поверх iroh QUIC)
- **`iroh-manager.js`** — полностью переработан: `startTunnelServer` / `startTunnelClient`, туннелирование TCP-подобного трафика через iroh bi-streams.
- **`main.js`** — запуск туннеля при старте стола + IPC-обработчики.
- **`preload.js`** — экспонированы методы tunnel-клиента.
- **Renderer** (`app.js`, HTML, `styles.css`):
  - поле ввода P2P-билета в экране подключения (`doJoinP2p()`);
  - `stopIrohForTable()` останавливает и туннель;
  - добавлен CSS `.join-p2p`, `.join-p2p__divider`.
- Fallback-заглушка `getIrohManager()` дополнена недостающими методами.

### 3. Тестирование
- Синтаксис всех изменённых JS — **OK**.
- Туннель проверен **end-to-end через два отдельных Node-процесса**: HTTP-запрос прошёл сквозь iroh-стримы (`200 pong from DM via tunnel`).
- Ошибка "Connecting to ourself" — артефакт одиночного процесса (ДМ и игрок делят endpoint); в реальном приложении это два процесса.
- Временные тест-файлы удалены.

## 🔧 Технические детали
- Сервер стола слушает `0.0.0.0:port` (доступен и на `127.0.0.1`).
- `createTableServer()` возвращает `{ port, addresses, localUrl, io, httpServer, close() }`.
- Песочница: Windows PowerShell 5.1 (нет `&&` — использовать `;`).
