# D&D Стол

Portable desktop-приложение на Electron для игры в **D&D 5e (2014)** напрямую
через P2P. Один участник — ДМ: он поднимает стол на своём компьютере. Остальные
подключаются к нему по P2P-билету и попадают за общий стол.

**Общей сети не нужно.** Приложение не создаёт сеть, не поднимает VPN и не
требует проброса портов. Игроки соединяются с мастером напрямую через
[P2P (iroh)](#подключение-по-p2p-iroh): общей папки, Hamachi, Radmin VPN,
ZeroTier и Porthole больше не существует, а сервер стола слушает только
`127.0.0.1` и наружу не выставлен.

> Актуальное состояние проекта, ключевые решения и известные ограничения
> описаны в спецификации [`openspec/specs/dnd-table/spec.md`](openspec/specs/dnd-table/spec.md).

Текущая версия — **0.12.1b**. В `package.json` она записана как `0.12.1-b`: строгий
semver — требование electron-builder, иначе сборка падает с «Invalid version».
В интерфейсе (окно настроек) показывается привычное **0.12.1b**, в именах файлов
сборки — `0.12.1-b`.

## Быстрый старт

```bash
npm install
npm start
```

Первое окно разделено на две группы: **«Мастеру»** (создать кампанию, загрузить
кампанию) и **«Игроку»** (подключиться к столу).

Игрок запускает **этот же** приложение, выбирает «Подключиться к столу»,
вставляет P2P-билет, который прислал мастер, своё имя и жмёт
«Подключиться по P2P».

### Проверки

```bash
npm test                      # сервер, импорт приключений и правила листа
node test/packaged-smoke.js   # собранное приложение: интерфейс и сквозной сценарий
```

`npm test` запускает `test/integration.js`, `test/importer.js` и `test/sheet.js`.
Точечно: `npm run test:importer`, `npm run test:sheet`.
Проверка интерфейса на исходниках, без пересборки: `npx electron test/smoke-main.js`
(её же гоняет `test/packaged-smoke.js`, но уже на собранном приложении).

## Подключение по P2P (iroh)

Единственный способ попасть на стол. Игра туннелирует socket.io поверх
QUIC-стримов iroh. iroh сам пробивает NAT — напрямую, а при неудаче через
публичный relay. VPN и проброс портов не нужны.

**Как это работает.** У мастера стол слушает `127.0.0.1:32100` и поднимается
iroh-endpoint, который принимает подключения игроков. Игрок вставляет билет
endpoint из панели «Приглашение игроков» на экране стола. У игрока поднимается
локальный TCP-туннель, и socket.io направляется на `127.0.0.1:<локальный порт>`;
дальше байты идут по QUIC до стола мастера.

**Требования:** нужен доступ в интернет (iroh использует relay и discovery n0),
плюс разрешение приложению на доступ к сети в брандмауэре Windows.

## Стол без сервера (проверка)

Кнопка **«▷ Запустить стол без сервера (как игрок)»** в настройках открывает
обычный экран стола, но без сети и без сервера: сервер не поднимается, порт
никто не слушает. За ним можно заранее заполнить лист персонажа и посмотреть на
игру глазами игрока, никого не собирая.

Что работает: лист персонажа (сохраняется на этом компьютере), кубики, чат,
вкладки карт (карту для проверки можно загрузить с диска), сетка на карте и
фишка — в тренировочном столе она сразу ваша, её можно таскать по карте и задать
ей картинку. Рисование карт и назначение фишек игрокам остаются за ДМ: в
тренировке их нет.

Лист можно вынести отдельным окном и здесь (кнопка «⧉ Отдельным окном»): окно
подключается не к серверу, а к той же заготовке листа, поэтому правки видны и в
основном окне, и в отдельном. Панель стола при этом сворачивается до иконок —
удобно держать лист на втором мониторе, пока проверяешь карту.

Карты, фишки и чат в этом режиме живут до закрытия окна: они никуда не
сохраняются (лист — исключение, он переживает перезапуск).

**Заготовка листа переезжает на настоящий стол.** Лист, заполненный без стола,
хранится в хранилище окна под локальным идентификатором игрока. Когда вы
подключаетесь к настоящему столу и у этого игрока на столе лист ещё пуст,
приложение спрашивает: «Отправить лист на стол?». Согласие отправляет заготовку
на сервер, отказ оставляет её только у вас. Если лист на столе уже заполнен,
вопрос не задаётся — ничего не перезаписывается молча.

## Сборка переносимого комплекта

```bash
npm install
npm run dist:portable  # собирает приложение и сразу делает готовую папку release/ и архив
```

`npm run dist:portable` — одна команда: она и собирает, и пакует. Отдельно
`npm run dist` запускать не нужно, он остался только для случая, когда нужно
распакованное приложение из `dist-final/`, без папки для отправки.

На Windows получится `release/D&D Стол/`, на Linux — то же самое с бинарником
`DND-Table`; в обоих случаях рядом лежит `portable.txt`, который включает
переносимый режим:

```
D&D Стол/
├── D&D Стол.exe        # игра: двойной щелчок, установка не нужна
├── resources/  locales/  *.dll ...   # всё, что нужно приложению
├── portable.txt        # включает портативный режим
├── ПРОЧТИ МЕНЯ.txt     # инструкция для получателя
└── data/               # сюда ложатся кампании, карты и картинки фишек
```

Передавать папку нужно **целиком**: рядом с exe лежат служебные папки, без них
игра не запустится. Каждому участнику нужна своя копия — тогда у каждого будет
свой локальный `playerId` и свой лист персонажа.

Повторный `npm run dist:portable` безопасен: файлы копируются поверх, а папка
`data` с вашими кампаниями не очищается. В **архив** кампании не попадают —
получателю уходит чистая игра (это проверяется при сборке). Если приложение
запущено, сборка откажется обновлять папку, пока вы его не закроете.

Обычной сборкой на GitHub занимается `.github/workflows/build.yml`: коммит в
`master` собирает комплекты под Windows и Linux, а тег `v*` дополнительно
публикует их в Releases.

### Проверки

```bash
npm test                      # сервер, импорт приключений и правила листа
node test/packaged-smoke.js   # собранное приложение: интерфейс и сквозной сценарий
```

Вторая проверка читает оглавление `app.asar`, запускает собранное приложение и
через DevTools-протокол выполняет внутри упакованного окна проверки интерфейса,
а затем распаковывает архив из `release/` во временную папку и убеждается, что
данные уходят в `data` рядом с игрой, а не в профиль Windows. Окна при этом не
показываются — при `DND_HIDE_WINDOW=1` (или флаге `--hidden`) окно создаётся
невидимым.

> Проверять сборку лучше не на томе `E:` — оттуда Electron падает в V8 script
> streaming. Скопируйте exe с `resources/` и `locales/` на другой диск.

### Иконка

`build/icon.ico` и `build/icon.png` генерируются скриптом

треугольник — условный вид кости d20 сверху. ICO содержит размеры 16–256 px,
PNG — 512 px для Linux.

## Сетевая модель

* HTTP + Socket.IO. Сервер живёт в **main-процессе** Electron и запускается
  только по команде ДМ.
* Слушает **только `127.0.0.1`**: в локальной сети и в интернете порт стола не
  виден. Единственный путь к серверу — туннель iroh, который прокладывается
  прямо в этот порт.
* Свободный порт выбирается автоматически: сначала перебираются порты от
  `32100`, если все заняты — порт выдаёт операционная система.
* При закрытии приложения и при остановке стола сервер корректно закрывается,
  а кампания сохраняется.

### Роли

ДМ определяется не «по желанию клиента», а по двум признакам одновременно:

1. подключение пришло с localhost, и
2. клиент предъявил `hostKey` — случайный секрет, который main-процесс создаёт
   при запуске стола и передаёт **только своему окну** через `preload`.

Игрок с неверным ключом (или из сети) получает роль `player` и не может
выполнять действия ДМ.

### Как игрок попадает на стол

1. ДМ запускает стол. В панели «Приглашение игроков» появляется P2P-билет.
2. ДМ нажимает на билет (или жмёт копирование) и отправляет его игрокам любым
   удобным способом: мессенджер, почта, голосом.
3. Игрок вставляет билет на экране «Подключиться к столу», вводит имя и жмёт
   «Подключиться по P2P».
4. У игрока поднимается локальный TCP-туннель, socket.io идёт на
   `127.0.0.1:<локальный порт>`, дальше — по QUIC напрямую к мастеру.

> Ни Hamachi, ни Radmin VPN, ни ZeroTier, ни Porthole больше не нужны: общей
> сети нет вообще. Нужен только интернет (для relay и discovery) и разрешение
> приложению на сеть в брандмауэре.

## Данные и portable-режим

По умолчанию данные лежат в папке приложения, которую отдаёт Electron:
`app.getPath('userData')` (путь показан на главном экране, там же кнопка
«Открыть папку данных»).

Чтобы приложение было полностью portable, положите рядом с `package.json`
(или рядом с `exe`) пустой файл **`portable.txt`** — тогда все данные будут
храниться в папке `./data` рядом с приложением, и всю папку можно носить
с собой на флешке.

```
data/
└── campaigns/
    └── <campaignId>/
        ├── campaign.json   # состояние кампании (JSON)
        └── files/          # загруженные карты и изображения фишек
```

Кампания содержит: `id`, название, даты создания и последнего сохранения,
версию формата и состояние стола — список игроков, листы персонажей, три карты,
активную карту, настройки сетки, фишки с позициями и назначениями, историю
бросков и чата.

### Сохранение

* Кнопка **«Сохранить кампанию»** на экране ДМ.
* **Автосохранение** раз в 60 секунд, если что-то менялось.
* Сохранение при остановке стола и при закрытии приложения.

### Переподключение игрока

Клиент генерирует и хранит локальный `playerId` в `localStorage`. При
подключении он отправляет имя и этот идентификатор; сервер по нему находит
прежний лист персонажа. Листы и данные игроков **не удаляются** при
отключении — игрок вернётся к своему персонажу.

## Загрузка изображений

Способ: **base64 через Socket.IO**, файлы складываются в папку кампании и
раздаются встроенным сервером.

1. Renderer читает выбранный файл через `FileReader` → `data:image/...;base64,...`
   (`renderer/app.js`, функция `readImageFile`).
2. Изображение уходит событием `uploadMap` (карты) или `setTokenImage` (фишки).
3. Сервер (`server/socket.js`, `decodeImage`) проверяет:
   * MIME — только `png`, `jpeg`, `webp`;
   * размер — не больше 10 МБ;
   * **сигнатуру файла** — реальный тип определяется по «магическим байтам»,
     поэтому подделка MIME не проходит.
4. Файл сохраняется в `<кампания>/files/<случайное-имя>.<ext>`, а клиентам
   уходит только URL `/files/<имя>`.
5. Раздача — `GET /files/:name`; путь защищён от выхода за папку кампании.

## Лист персонажа (D&D 5e 2014)

Поля: имя персонажа и игрока, класс, раса, предыстория, мировоззрение, уровень,
опыт, бонус мастерства, шесть характеристик, их модификаторы, спасброски,
18 навыков, хиты, максимальные и временные хиты, кость хитов, класс брони,
инициатива, скорость, пассивное восприятие, атаки и заклинания, снаряжение,
особенности и черты, заметки.

Считается автоматически (`renderer/dnd5e.js`):

| Величина | Формула |
| --- | --- |
| Модификатор характеристики | `floor((значение − 10) / 2)` |
| Бонус мастерства | по уровню: 1–4 → +2, 5–8 → +3, 9–12 → +4, 13–16 → +5, 17–20 → +6 |
| Спасбросок / навык с владением | модификатор + бонус мастерства |
| Навык с компетентностью | модификатор + 2 × бонус мастерства |
| Пассивное восприятие | 10 + бонус Внимательности |
| Инициатива | модификатор Ловкости + прочий бонус |

Бонус мастерства можно задать вручную (галочка на листе) — для домашних правил.

Лист хранится **на сервере** и синхронизируется:

* игрок видит и редактирует только свой лист и не может получить чужой
  (проверяется на сервере);
* во вкладке «Лист» у ДМ сначала открывается **список игроков**: нажатие на имя
  открывает лист этого игрока **в режиме просмотра**, кнопка «← К списку
  игроков» возвращает обратно. Пока никто не подключился, там написано «В лобби
  сейчас никого нет». Тот же лист можно открыть кнопкой «Открыть лист» в списке
  участников слева; открытый лист обновляется на лету при правках игрока.
* кнопка **«⧉ Отдельным окном»** выносит лист в отдельное окно приложения: его
  можно отодвинуть на второй монитор и работать с листом, не занимая панель
  стола. Игрок открывает так свой лист (и может в нём править), ДМ — лист
  выбранного игрока (только просмотр). Окно подключается к тому же столу тем же
  персонажем, поэтому правки видны и в основном окне, и здесь. В тренировочном
  столе (без сервера) окно работает так же, но берёт лист из общей заготовки
  листа, а не со стола. После выноса листа панель стола сворачивается до иконок.

## Карты, сетка, фишки, рисование карт, кубики, чат

* **Три вкладки карт**: «Общая карта», «Карта локации / битвы» и «Рисунок».
  **Во вкладке можно держать несколько карт** — ДМ загружает сколько нужно и
  переключается между ними стрелками «◀ ▶» или списком; прежние карты никуда не
  пропадают. Игрокам показывается выбранная карта той вкладки, для которой горит
  зелёная точка; вкладки позволяют заглянуть во вторую — с пометкой, что ДМ
  показывает другую. Удаляется только та карта, которую выбрал ДМ.
* **Приближение карты** — у каждого своё. Кнопки «−», «+» и «⤢ Сбросить» в углу
  карты, колесо мыши (приближает к точке под курсором) и перетаскивание карты
  мышью. Карта, сетка и фишки увеличиваются вместе, как если бы вы наклонились
  к столу: размер клетки и фишек относительно карты не меняется, а на других
  участников ваше приближение не влияет.
* **Сворачиваемые панели**: «◀ Участники» убирает левую панель совсем, «Панель ▸»
  сворачивает правую до иконок вкладок чата, кубиков, листа и фишек (клик по
  иконке разворачивает панель обратно). Выбор запоминается.
* **Сетка на карте**. Включается кнопкой «Сетка» в панели карты или галочкой в
  настройках. Клетка **ровно по размеру фишки**: фишка занимает клетку целиком,
  в обоих режимах и при любом увеличении.
  * **Ручной размер** — список значений в пикселях (по умолчанию 46 px).
  * **Подгонка под карту** — поле «клеток по ширине карты»: мастер пишет, сколько
    клеток укладывается по ширине (например, 20), и размер клетки считается от
    настоящей ширины подложки. Сетка одинаково ровная на любой карте и всегда
    делит её нацело. Значение 0 возвращает ручной режим.

  Число клеток хранится в кампании и приходит всем участникам, поэтому сетка
  одинаковая у всех; считает её каждый сам от своей копии подложки, результат
  совпадает. Сетку и размер задаёт ДМ.
* **Рисование карты самому**. Кнопка «Нарисовать карту» (или «Рисовать поверх
  карты», если карта уже загружена) открывает холст: кисть, линия,
  прямоугольник, ластик, цвет и его палитра, толщина, отмена штриха, очистка,
  привязка начала и конца штриха к клеткам. Подложкой можно взять любую
  загруженную карту или файл — рисунок ляжет поверх неё (подложка не
  растягивается, размер холста всегда кратен клетке, поэтому линии ложатся
  ровно). На пустой вкладке холст сам берёт карту, показанную игрокам, чтобы не
  начинать с пустого листа. Кнопкой «Сделать картой» рисунок сохраняется в любую
  из трёх карт; ластик стирает только штрихи и не портит подложку.
* **Фишки**. ДМ создаёт фишки, задаёт имя, назначает игроку, загружает
  изображение, перемещает и удаляет любые фишки. Правый клик по фишке открывает
  меню: переименовать, изображение, назначить игроку, скрыть, удалить. Игрок
  перемещает только свою фишку и может загрузить для неё картинку. Координаты
  хранятся долями от размера карты (`x`, `y` от 0 до 1), поэтому у всех
  участников фишки стоят одинаково. Перетаскивание — мышью или пальцем
  (Pointer Events).
* **Скрытие фишек**. Новая фишка появляется **скрытой от игроков**: мастер
  сначала расставляет её и проверяет расстановку, потом открывает. Скрытая
  фишка видна только мастеру и помечена пунктиром, чтобы её не спутать с
  готовой. Открыть и снова спрятать можно и по одной (правый клик по фишке или
  кнопка «Скрыта» / «Видна» в списке фишек), и разом кнопками «Показать все»
  и «Скрыть все». Скрытым фишкам никто из игроков не получает ни положения,
  ни картинки, ни переименований — и в списке участников у игрока не появляется
  отметки о фишке, которую он не должен знать.
* **Фишка из листа**. Кнопка «Вывести» есть в двух местах: у игрока в списке
  участников и в панели фишек, отдельным блоком «Вывести из листа». Обе
  делают одно и то же: мастер выводит фишку прямо из листа — с именем
  персонажа и аватаром игрока, на текущей вкладке карт, сразу назначенную
  ему. Повторно кнопка не появляется, пока фишка уже есть: одна фишка на
  человека. Когда фишки есть у всех, блок так и говорит и списка не держит.
  Фишка, выведенная из листа, **живёт аватаром**: игрок сменил портрет — фишка
  обновилась сама. Но стоит поставить ей картинку руками, и аватар её больше не
  трогает, чтобы не затереть то, что нарисовали специально.
* **Кубики**: d1…d20. Бросок выполняет **сервер**, результат рассылается всем
  вместе с именем и временем. `d1` всегда даёт 1. Бросок дублируется в чат,
  история бросков хранится за сессию и попадает в кампанию.
* **Чат**: общий, с именем автора и временем. У броска кубика перед именем
  стоит портрет бросившего — так сразу видно, чей это результат. Портрет
  пишется в само сообщение, поэтому в истории остаётся тот, каким был в момент
  броска. История за сессию; последние сообщения сохраняются с кампанией.
* **Список игроков**: портрет (или буква имени, если портрета нет), имя, роль
  (ДМ / игрок), статус в сети, у ДМ — кнопки «Фишка на поле» и «Открыть лист».
* **Аватар**. Игрок ставит портрет в своём листе, в блоке «Персонаж»:
  PNG, JPG или WEBP до 2 МБ. Портрет виден всему столу — в списке участников и
  у бросков в чате, — но это картинка, а не данные листа, поэтому чужие
  характеристики она не раскрывает. Меняет аватар только сам игрок, даже мастер
  в чужом листе кнопку не видит. У мастера, пока он не поставил свой, есть
  портрет из поставки: мудрый старец-архимаг. Свой портрет мастер меняет
  в списке игроков, блок «Ваш портрет»: своего листа персонажа у него нет,
  поэтому портрет живёт именно там.
* **Настройки** (кнопка «⚙ Настройки» на главном экране и на столе): версия,
  режим, папка данных, **оформление**, язык интерфейса, а за столом у ДМ —
  сетка и размер клетки.
  Вне стола здесь же лежит запуск стола без сервера (см. «Стол без сети»).
  Панель «Адреса для подключения» сворачивается кнопкой «Скрыть», в свёрнутом
  виде показывает основной адрес.

## Темы оформления

Пять палитр, переключаются в «Настройках» → «Оформление» и применяются сразу,
без перезапуска:

| Тема | Вид |
|---|---|
| **Стандартная** | та, что была до тем: тёплый коричневый и охра |
| **Лес** | холодная зелень, тёмная хвоя, светлый мох |
| **Магия** | чернильный фиолетовый, светящаяся лоза |
| **Океан** | глубокая вода, холодный свет, пена |
| **Трактир** | тёплое дерево, охра и свечной свет |

Каждая тема переопределяет один и тот же набор переменных (`--bg`, `--surface`,
`--border`, `--text`, `--accent`, `--gold`, `--danger`, `--ok`), поэтому разметка
не меняется. Чтобы добавить тему, достаточно описать эти поля в `styles.css` и
дописать строку в список `THEMES` в `renderer/theme.js`.

### Общий слой оформления

Кроме цвета, у всех тем есть общий «настольный» слой: он задаётся общими
переменными и одинаково работает в каждой палитре.

* **Гравировка.** У панелей светлая кромка сверху и тень снизу, у кнопок —
  блик по верхней грани. Плоские заливки выглядели бы как цветные прямоугольники,
  а не как вырезанные из камня детали.
* **Шрифты.** Заголовки — дисплейный шрифт с разрядкой, подписи панелей —
  капитель, числа (кубики, модификаторы, характеристики) — табличные, чтобы
  цифры не прыгали при изменении.
* **Орнамент.** Логотип — гранёная пластина с ромбом, пустая карта помечена
  водяным знаком гранёного куба, заголовки панелей подчёркнуты волосяной линией.
* **Движение.** Экраны и панели проявляются, карточки главного экрана
  поднимаются по очереди, строки чата и списков въезжают сбоку, бросок кубика
  выскакивает и расходится кольцом, тосты и модальные окна расплываются, а
  блеск пробегает по карточке при наведении.
* **Фактура.** Поверх всего — едва заметное зерно: интерфейс выглядит скорее
  напечатанным, чем нарисованным.

### Чем темы отличаются помимо цвета

* **Рамки.** Своя толщина и начертание (`--frame`), своя внутренняя обводка,
  своё скругление: у «Трактира» углы почти прямые и рамка вдвое толще, у «Океана»
  панели сильно скруглены, у «Магии» двойная обводка и светящиеся уголки, у
  «Леса» скругление неровное, как у листа. Панели и карточки на главном экране
  рисуют уголки линиями цвета темы.
* **Анимации.** Подложка-атмосфера под всем содержимым: в «Лесу» ползут пятна
  солнца, в «Магии» проступают искры, в «Океане» идёт волна, в «Трактире» дрожит
  неровный свет свечей. Заголовки дышат в такт теме.
* **Шрифты.** Заголовочная гарнитура одна на все темы: тонкая антиква Cormorant,
  набранная как надпись на старинной книге. Тема меняет её характер — начертание,
  разрядку и насыщенность: «Магия» тонкая и просторная, «Трактир» плотный и весомый,
  «Океан» светлый, «Лес» сдержанный. Раньше у каждой темы был свой шрифт, и часть
  из них (Rockwell, Bahnschrift) кириллицы не содержит: русские заголовки молча уходили
  в подстановочный шрифт, и заголовок выглядел сломанным. Теперь русский набирается
  той же гарнитурой, что и латиница.
  Основной текст — системный Segoe UI: он спокойный, разборчивый и не тяжелит сборку.
  Заголовочный шрифт лежит рядом с интерфейсом (`renderer/fonts`), а не тянется из сети:
  игра работает офлайн. Подмножества разделены по файлам, кириллица весит отдельно.

Анимируется только `transform` и `opacity`, поэтому карта с кучей фишек не
просядет. То же и с расчётом координат: у фишек не двигается `transform`, иначе
прыжок броска сбился бы. Системная настройка «уменьшить движение» отключает
анимации, оформление остаётся. Темы связаны только переменными: разметка и
поведение у всех тем одни и те же.

Тема — дело каждого: она хранится в настройках этого компьютера, а не в кампании,
поэтому игроки видят стол в своей палитре. Выбор применяется до первой отрисовки
(скрипт подключён раньше стилей) и расходится на окно листа персонажа.

### Шрифты

Заголовочный шрифт — **Cormorant** (Christian Thalmann, SIL Open Font License 1.1),
  он лежит в `renderer/fonts` вместе с лицензией `OFL.txt`. Файлы разделены по
  подмножествам: браузер подгружает только нужное, кириллица не тащится вместе с
  латиницей. Обновляется скриптом:

```bash
node scripts/fetch-fonts.js
```

Без интернета игра работает как обычно: шрифт уже лежит рядом с интерфейсом.

### Как посмотреть на оформление

`scripts/make-shots.js` Снимает главный экран, стол, лист и экран подключения
в каждой теме:

```bash
npx electron scripts/make-shots.js [папка]
```

Снимки складываются в `shots/` (в репозитории их нет). Нужен, чтобы оценить
оформление глазами: правила CSS ничего не говорят о том, как это выглядит.

## События Socket.IO

`client → server`:
`joinRoom {name, playerId, hostKey}`, `saveCharacterSheet {sheet}`,
`requestCharacterSheet {playerId}`, `uploadMap {type, image, name}`,
`selectMap {type, mapId}`, `deleteMap {type, mapId}`, `setActiveMap {type}`,
`setGrid {enabled, cell}`,
`createToken {name, mapType}`,
`renameToken {tokenId, name}`, `assignTokenToPlayer {tokenId, playerId}`,
`setTokenImage {tokenId, image}`, `moveToken {tokenId, x, y}`,
`deleteToken {tokenId}`, `rollDice {sides}`, `chatMessage {text}`.

`server → client`:
`joined {you, state}`, `playersUpdate […]`, `characterSheetData {playerId, sheet}`,
`characterSheetUpdated {playerId, sheet}`,
`mapUpdated {type, items, activeId, activeMap}`,
`gridUpdated {enabled, cell}`,
`tokenCreated token`, `tokenUpdated token`, `tokenMoved {tokenId, x, y}`,
`tokenDeleted {tokenId}`, `diceRollResult {playerId, playerName, sides, result, time}`,
`chatMessage {from, role, text, time, isRoll?}`, `errorMessage {message}`.

Дополнительно: `joined` (полный снимок состояния при входе) и `renameToken`
(переименование фишки ДМом). Тип карты `type` — один из `world` (общая),
`battle` (локация) и `sketch` (рисунок ДМа); `items` — карты этой вкладки в
порядке загрузки, `activeId` — какую из них показывать.
`uploadMap` добавляет карту к уже загруженным в вкладке, а не заменяет прежние.

## Кампании: IPC main ↔ renderer

`campaign:create`, `campaign:list`, `campaign:load`, `campaign:save`,
`campaign:delete`, `campaign:current`, `host:start`, `host:stop`, `host:status`,
`app:config`, `shell:openDataDir`, `shell:openExternal` (только http/https),

## Безопасность

* `contextIsolation: true`, `nodeIntegration: false`; renderer видит только то,
  что перечислено в `preload.js`.
* Роль ДМ проверяется на сервере (loopback + `hostKey`).
* Сервер стола слушает только `127.0.0.1`: из локальной сети и из интернета на
  него нельзя попасть в принципе, а к туннелю iroh допускается только тот, у
  кого есть билет мастера.
* Игрок не может получить чужой лист, двигать или удалить чужую фишку,
  управлять картами и кампаниями — это проверяется на сервере, а не только
  скрытием кнопок в интерфейсе.
* Имя и сообщения обрезаются по длине, пустые отклоняются; изображения —
  по типу (включая сигнатуру) и размеру.
* CSP в `index.html` ограничивает источники скриптов и стилей.
* Файлы картинок (`GET /files/:name`) отдаются с заголовком
  `Access-Control-Allow-Origin: *` — иначе renderer не смог бы положить
  загруженную карту на холст для рисования (браузер считает такой холст
  «загрязнённым»). Доступны только файлы текущей кампании из папки `files`.

### Известное ограничение

У игрока нет пароля: привязка к прежнему листу персонажа идёт по локальному
`playerId`, который сообщает клиент (так требует сценарий переподключения).
Чтобы выдать себя за другого, злоумышленнику нужно знать чужой UUID — то есть
получить доступ к компьютеру игрока. Билет мастера — единственный барьер на
входе, поэтому передавайте его только тем, кто реально за столом.
