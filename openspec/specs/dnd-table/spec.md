# dnd-table

Актуальная спецификация портативного настольного приложения **«D&D Стол»** для игры в D&D 5e (2014) по локальной или виртуальной сети, а также напрямую через P2P.

## Purpose

Один человек поднимает стол и ведёт игру как Мастер, остальные подключаются к нему как игроки. Стол живёт в процессе Electron: приложение само поднимает сервер на своём компьютере, не требуя установки, учётных записей или внешних сервисов.

Ключевое свойство: **приложение не создаёт сеть и не поднимает VPN**. Оно использует уже существующую локальную или виртуальную сеть, проброс порта (Porthole) либо прямое P2P-соединение через iroh.

## Requirements

### Requirement: Переносимость и портативность
Приложение SHALL работать из обычной папки без установки и без прав администратора.

#### Scenario: Данные хранятся рядом с игрой
- **WHEN** пользователь запускает сборку, в папке которой лежит `portable.txt`
- **THEN** кампании, карты и картинки складываются в подпапку `data` рядом с exe, а не в профиль Windows
- **AND** перенос папки целиком переносит всю игру

#### Scenario: Комплект для отправки
- **WHEN** выполняется `npm run dist:portable`
- **THEN** в `release/<productName>/` появляется готовый комплект с exe, `portable.txt` и папкой `data`
- **AND** архив `<productName>.zip` проверяется распаковкой во временную папку

### Requirement: Стол и роли участников
Система SHALL поднимать стол в процессе приложения и раздавать роли по ключу хоста.

#### Scenario: Мастер поднимает стол
- **WHEN** пользователь создаёт кампанию и запускает стол
- **THEN** поднимается сервер на свободном порте, предпочитая 32100
- **AND** на экране появляются адреса для подключения с портом

#### Scenario: Роль выдаётся только по ключу хоста
- **WHEN** клиент подключается к столу
- **THEN** роль DM выдаётся только при loopback-адресе **и** совпадении `hostKey`
- **AND** иначе клиент получает роль игрока

### Requirement: Лист персонажа по D&D 5e (2014)
Система SHALL считать производные значения листа автоматически.

#### Scenario: Производные значения пересчитываются
- **WHEN** меняется уровень или характеристика
- **THEN** модификатор равен `floor((значение − 10) / 2)`
- **AND** бонус мастерства, спасброски и навыки пересчитываются по правилам 2014 года

#### Scenario: Приватность листов
- **WHEN** игрок подключён к столу
- **THEN** он видит только свой лист
- **AND** лист другого игрока он запросить не может

### Requirement: Прямое P2P-соединение через iroh
Система SHALL соединять игрока со столом напрямую, без общей сети и VPN, используя билета iroh-endpoint.

#### Scenario: Мастер публикует билет
- **WHEN** стол запущен
- **THEN** поднимается iroh-endpoint и туннель на порт стола
- **AND** в панели адресов появляется билет с кнопкой копирования

#### Scenario: Игрок подключается по билету
- **WHEN** игрок вставляет билет и нажимает «Подключиться по P2P»
- **THEN** поднимается локальный TCP-туннель, и socket.io направляется на `127.0.0.1:<локальный порт>`
- **AND** socket.io использует только транспорт `websocket`, потому что `polling` открыл бы много отдельных QUIC-стримов

#### Scenario: Один endpoint на процесс
- **WHEN** стол и renderer одновременно запрашивают запуск iroh
- **THEN** поднимается ровно один endpoint
- **AND** билет и accept-цикл относятся к одному адресу, иначе подключение игрока всегда упирается в таймаут

#### Scenario: Туннель переживает переподключение socket.io
- **WHEN** игрок только что поднял туннель и вызывает подключение к столу
- **THEN** переподключение socket.io SHALL NOT закрывать локальный TCP-порт туннеля
- **AND** иначе клиент получает `ERR_CONNECTION_REFUSED`

### Requirement: Интерфейс на главном экране
Главный экран SHALL предлагать действия, сгруппированные по роли, без дублирующих кнопок.

#### Scenario: Группы действий
- **WHEN** открывается главный экран
- **THEN** есть группа «Мастеру» (создать кампанию, загрузить кампанию)
- **AND** есть группа «Игроку» (подключиться к столу — по адресу или по P2P-билету)
- **AND** P2P не дублируется отдельными кнопками на главном экране

#### Scenario: Билет всегда под рукой у Мастера
- **WHEN** стол запущен
- **THEN** билет для раздачи игрокам доступен на экране стола, а не только на главном экране

## Структура проекта

| Путь | Назначение |
|---|---|
| `main.js` | main-процесс: окна, IPC, папка данных, автосохранение |
| `preload.js`, `preload-sheet.js` | мосты main → renderer, contextIsolation включён |
| `renderer/app.js` | состояние интерфейса, экраны, подключение к столу |
| `renderer/table.js` | стол: карта, фишки, сетка, участники, кубики, чат |
| `renderer/sheet.js`, `dnd5e.js` | лист персонажа и правила 5e (2014) |

| `renderer/styles.css` | оформление, в том числе группировка главного экрана |
| `server/socket.js` | сервер стола: Express + Socket.IO, авторизация по `hostKey` |
| `server/state.js` | состояние комнаты, листы, карты, кубики, чат |
| `server/campaign.js` | хранение кампаний на диске |
| `server/iroh-manager.js` | P2P: endpoint, билеты, туннели клиента и сервера |
| `server/net.js` | выбор свободного порта, локальные адреса |
| `scripts/make-portable.js` | сборка комплекта для отправки и архива |
| `test/integration.js` | 84 проверки сервера и хранения данных |
| `test/packaged-smoke.js` | 198 проверок внутри собранного приложения |
| `test/renderer-assertions.js` | сценарии интерфейса, исполняемые через CDP |
| `build/icon.ico` | иконка для electron-builder |

## Заметки и ограничения

- **Сборочные артефакты.** `dist-final/` и `release/` пересоздаются командами `npm run dist` и `npm run dist:portable`. Внутри `release/` лежит папка `data` с кампаниями пользователя — при сборке она намеренно не очищается.
- **Нативная зависимость.** `@number0/iroh@1.1.0` публикуется с неверным полем `main` (`iroh-js/index.js`), которого в пакете нет. `server/iroh-manager.js` обходит это, подключая `index.js` из корня пакета; при `require('@number0/iroh')` P2P выключался бы молча.
- **Тестовые скрипты в `package.json` не объявлены.** Проверки запускаются напрямую: `node test/integration.js` и `node test/packaged-smoke.js`. HANDOFF-подобных документов, на которые ссылались бы эти команды, в проекте больше нет.
- **Проверки карт в `integration.js` чувствительны к порядку событий.** Журнал `mapUpdated` очищается перед каждой операцией: иначе `waitFor` удовлетворяется событием от предыдущей операции и проверка читает сервер до применения карты.
- **Автоматическая сборка.** `.github/workflows/build.yml` собирает переносимые комплекты под Windows и Linux: коммит в `master` — артефакты сборки, тег `v*` — публикация в Releases. Используются только официальные actions GitHub и `gh` из стандартного образа.
- **Запуск из корня диска `E:`.** Собранный exe на этом томе падает в V8 script streaming. Тот же бинарник из `C:\` работает. Для проверки сборку нужно распаковывать на другой диск.
- **Зависимости:** `@number0/iroh`, `express`, `socket.io`. Сборка: `electron` 28.3.3, `electron-builder` 26.15.3.
