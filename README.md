# D&D Стол

Portable desktop-приложение на Electron для игры в **D&D 5e (2014)** напрямую
через P2P. Один участник — ДМ: он поднимает стол на своём компьютере. Остальные
подключаются к нему по P2P-билету и попадают за общий стол.

**Общей сети не нужно.** Приложение не создаёт сеть, не поднимает VPN и не
требует проброса портов. Игроки соединяются с мастером напрямую через
[P2P (iroh)](#подключение-по-p2p-iroh): общей папки, Hamachi, Radmin VPN,
ZeroTier и Porthole больше не существует, а сервер стола слушает только
`127.0.0.1` и наружу не выставлен.

> Актуальное состояние проекта, ключевые решения и известные ограничения
> описаны в спецификации [`openspec/specs/dnd-table/spec.md`](openspec/specs/dnd-table/spec.md).

Текущая версия — **1.0b**. В `package.json` она записана как `1.0.0-b`: строгий
semver — требование electron-builder, иначе сборка падает с «Invalid version».
В интерфейсе (окно настроек) показывается привычное **1.0b**, в именах файлов
сборки — `1.0.0-b`.

## Быстрый старт

```bash
npm install
npm start
```

Первое окно разделено на две группы: **«Мастеру»** (создать кампанию, загрузить
кампанию) и **«Игроку»** (подключиться к столу).

Игрок запускает **этот же** приложение, выбирает «Подключиться к столу»,
вставляет P2P-билет, который прислал мастер, своё имя и жмёт
«Подключиться по P2P».

### Проверки

```bash
npm test                      # сервер, импорт приключений и правила листа
node test/packaged-smoke.js   # собранное приложение: интерфейс и сквозной сценарий
```

`npm test` запускает `test/styles.js`, `test/integration.js`, `test/importer.js`
и `test/sheet.js`. Точечно: `npm run test:importer`, `npm run test:sheet`.
`test/styles.js` Проверяет оформление: порядок частей и то, что смысловые цвета
объявлены и используются, а не зашиты в правила.
Проверка интерфейса на исходниках, без пересборки: `npx electron test/smoke-main.js`
(её же гоняет `test/packaged-smoke.js`, но уже на собранном приложении).

## Подключение по P2P (iroh)

Единственный способ попасть на стол. Игра туннелирует socket.io поверх
QUIC-стримов iroh. iroh сам пробивает NAT — напрямую, а при неудаче через
публичный relay. VPN и проброс портов не нужны.

**Как это работает.** У мастера стол слушает `127.0.0.1:32100` и поднимается
iroh-endpoint, который принимает подключения игроков. Игрок вставляет билет
endpoint из панели «Приглашение игроков» на экране стола. У игрока поднимается
локальный TCP-туннель, и socket.io направляется на `127.0.0.1:<локальный порт>`;
дальше байты идут по QUIC до стола мастера.

**Требования:** нужен доступ в интернет (iroh использует relay и discovery n0),
плюс разрешение приложению на доступ к сети в брандмауэре Windows.

## Стол без сервера (проверка)

Кнопка **«▷ Запустить стол без сервера (как игрок)»** в настройках открывает
обычный экран стола, но без сети и без сервера: сервер не поднимается, порт
никто не слушает. За ним можно заранее заполнить лист персонажа и посмотреть на
игру глазами игрока, никого не собирая.

Что работает: лист персонажа (сохраняется на этом компьютере), кубики, чат,
вкладки карт (карту для проверки можно загрузить с диска), сетка на карте и
фишка — в тренировочном столе она сразу ваша, её можно таскать по карте и задать
ей картинку. Рисование карт и назначение фишек игрокам остаются за ДМ: в
тренировке их нет.

Лист можно вынести отдельным окном и здесь (кнопка «⧉ Отдельным окном»): окно
подключается не к серверу, а к той же заготовке листа, поэтому правки видны и в
основном окне, и в отдельном. Панель стола при этом сворачивается до иконок —
удобно держать лист на втором мониторе, пока проверяешь карту.

Карты, фишки и чат в этом режиме живут до закрытия окна: они никуда не
сохраняются (лист — исключение, он переживает перезапуск).

**Заготовка листа переезжает на настоящий стол.** Лист, заполненный без стола,
хранится в хранилище окна под локальным идентификатором игрока. Когда вы
подключаетесь к настоящему столу и у этого игрока на столе лист ещё пуст,
приложение спрашивает: «Отправить лист на стол?». Согласие отправляет заготовку
на сервер, отказ оставляет её только у вас. Если лист на столе уже заполнен,
вопрос не задаётся — ничего не перезаписывается молча.

## Сборка переносимого комплекта

```bash
npm install
npm run dist:portable  # собирает приложение и сразу делает готовую папку release/ и архив
```

`npm run dist:portable` — одна команда: она и собирает, и пакует. Отдельно
`npm run dist` запускать не нужно, он остался только для случая, когда нужно
распакованное приложение из `dist-final/`, без папки для отправки.

На Windows получится `release/D&D Стол/`, на Linux — то же самое с бинарником
`DND-Table`; в обоих случаях рядом лежит `portable.txt`, который включает
переносимый режим:

```
D&D Стол/
├── D&D Стол.exe        # игра: двойной щелчок, установка не нужна
├── resources/  locales/  *.dll ...   # всё, что нужно приложению
├── portable.txt        # включает портативный режим
├── ПРОЧТИ МЕНЯ.txt     # инструкция для получателя
└── data/               # сюда ложатся кампании, карты и картинки фишек
```

Передавать папку нужно **целиком**: рядом с exe лежат служебные папки, без них
игра не запустится. Каждому участнику нужна своя копия — тогда у каждого будет
свой локальный `playerId` и свой лист персонажа.

Повторный `npm run dist:portable` безопасен: файлы копируются поверх, а папка
`data` с вашими кампаниями не очищается. В **архив** кампании не попадают —
получателю уходит чистая игра (это проверяется при сборке). Если приложение
запущено, сборка откажется обновлять папку, пока вы его не закроете.

Обычной сборкой на GitHub занимается `.github/workflows/build.yml`: коммит в
`master` собирает комплекты под Windows и Linux, а тег `v*` дополнительно
публикует их в Releases.

Описание релиза лежит в репозитории отдельным файлом
`docs/release-notes-<версия>.md` — с расширением `-b` в имени, как в
`package.json`. Сборка копирует его в описание релиза; если файла нет, описание
будет состоять из одной строки с версией. Текст прямо в YAML для этого не
годится: закрывающий маркер heredoc в многострочном русском тексте отправлял
в описание мусор, и релиз 0.12.2 ушёл с ним.

### Проверки

```bash
npm test                      # сервер, импорт приключений и правила листа
node test/packaged-smoke.js   # собранное приложение: интерфейс и сквозной сценарий
```

Вторая проверка читает оглавление `app.asar`, запускает собранное приложение и
через DevTools-протокол выполняет внутри упакованного окна проверки интерфейса,
а затем распаковывает архив из `release/` во временную папку и убеждается, что

показываются — при `DND_HIDE_WINDOW=1` (или флаге `--hidden`) окно создаётся
невидимым.

> Проверять сборку лучше не на томе `E:` — оттуда Electron падает в V8 script
> streaming. Скопируйте exe с `resources/` и `locales/` на другой диск.

### Иконка

`build/icon.ico` и `build/icon.png` генерируются скриптом
`scripts/make-icon.js` без внешних зависимостей: диск, шестиугольник и вписанный
треугольник — условный вид кости d20 сверху. ICO содержит размеры 16–256 px,
PNG — 512 px для Linux.

## Сетевая модель

* HTTP + Socket.IO. Сервер живёт в **main-процессе** Electron и запускается
  только по команде ДМ.
* Слушает **только `127.0.0.1`**: в локальной сети и в интернете порт стола не
  виден. Единственный путь к серверу — туннель iroh, который прокладывается
  прямо в этот порт.
* Свободный порт выбирается автоматически: сначала перебираются порты от
  `32100`, если все заняты — порт выдаёт операционная система.
* При закрытии приложения и при остановке стола сервер корректно закрывается,
  а кампания сохраняется.

### Роли

ДМ определяется не «по желанию клиента», а по двум признакам одновременно:

1. подключение пришло с localhost, и
2. клиент предъявил `hostKey` — случайный секрет, который main-процесс создаёт
   при запуске стола и передаёт **только своему окну** через `preload`.

Игрок с неверным ключом (или из сети) получает роль `player` и не может
выполнять действия ДМ.

### Своё имя

По умолчанию мастер под столом — «Мастер». Своё имя он задаёт двумя способами:

* кнопкой **«Имя»** в своей строке списка участников (там же, где написано
  «это вы»);
* полем **«Ваше имя за столом»** в «Настройках» — на главном экране и за столом.

Имя видно сразу всем участникам: оно стоит в списке участников и под чужими
бросками в чате. Оно же хранится на этом компьютере, поэтому стол, поднятый
позже, или переподключение приходят с тем же именем. Свой `playerId` в запросе
сервер игнорирует: переименоваться можно только самому себе, а чужое имя в чате
и в списке участников подделать нельзя.

Переименование мастера не затирает имя персонажа в листе, если оно вписано
руками: в листе «Мира» остаётся «Мирой», даже когда участника переименовали в
«Артёма». Автоматически подставленное имя участника, наоборот, едет вместе с ним.

### Как игрок попадает на стол

1. ДМ запускает стол. В панели «Приглашение игроков» появляется P2P-билет.
2. ДМ нажимает на билет (или жмёт копирование) и отправляет его игрокам любым
   удобным способом: мессенджер, почта, голосом.
3. Игрок вставляет билет на экране «Подключиться к столу», вводит имя и жмёт
   «Подключиться по P2P».
4. У игрока поднимается локальный TCP-туннель, socket.io идёт на
   `127.0.0.1:<локальный порт>`, дальше — по QUIC напрямую к мастеру.

> Ни Hamachi, ни Radmin VPN, ни ZeroTier, ни Porthole больше не нужны: общей
> сети нет вообще. Нужен только интернет (для relay и discovery) и разрешение
> приложению на сеть в брандмауэре.

## Данные и portable-режим

По умолчанию данные лежат в папке приложения, которую отдаёт Electron:
`app.getPath('userData')` (путь показан на главном экране, там же кнопка
«Открыть папку данных»).

Чтобы приложение было полностью portable, положите рядом с `package.json`
(или рядом с `exe`) пустой файл **`portable.txt`** — тогда все данные будут
храниться в папке `./data` рядом с приложением, и всю папку можно носить
с собой на флешке.

```
data/
└── campaigns/
    └── <campaignId>/
        ├── campaign.json   # состояние кампании (JSON)
        └── files/          # загруженные карты и изображения фишек
```

Кампания содержит: `id`, название, даты создания и последнего сохранения,
версию формата и состояние стола — список игроков, листы персонажей, три карты
с их туманом, стенами, светом и поверхностью, активную карту, настройки сетки,
режим боя, фишки с позициями и назначениями, историю бросков и чата.

### Сохранение

* Кнопка **«Сохранить кампанию»** на экране ДМ.
* **Автосохранение** раз в 60 секунд, если что-то менялось.
* Сохранение при остановке стола и при закрытии приложения.

### Переподключение игрока

Клиент генерирует и хранит локальный `playerId` в `localStorage`. При
подключении он отправляет имя и этот идентификатор; сервер по нему находит
прежний лист персонажа. Листы и данные игроков **не удаляются** при
отключении — игрок вернётся к своему персонажу.

## Загрузка изображений

Способ: **base64 через Socket.IO**, файлы складываются в папку кампании и
раздаются встроенным сервером.

1. Renderer читает выбранный файл через `FileReader` → `data:image/...;base64,...`
   (`renderer/app.js`, функция `readImageFile`).
2. Изображение уходит событием `uploadMap` (карты) или `setTokenImage` (фишки).
3. Сервер (`server/socket.js`, `decodeImage`) проверяет:
   * MIME — только `png`, `jpeg`, `webp`;
   * размер — не больше 10 МБ;
   * **сигнатуру файла** — реальный тип определяется по «магическим байтам»,
     поэтому подделка MIME не проходит.
4. Файл сохраняется в `<кампания>/files/<случайное-имя>.<ext>`, а клиентам
   уходит только URL `/files/<имя>`.
5. Раздача — `GET /files/:name`; путь защищён от выхода за папку кампании.

## Лист персонажа (D&D 5e 2014)

Поля: имя персонажа и игрока, класс, раса, предыстория, мировоззрение, уровень,
опыт, бонус мастерства, шесть характеристик, их модификаторы, спасброски,
18 навыков, хиты, максимальные и временные хиты, кость хитов, класс брони,
инициатива, скорость, пассивное восприятие, атаки и заклинания, снаряжение,
особенности и черты, заметки.

Считается автоматически (`renderer/dnd5e.js`):

| Величина | Формула |
| --- | --- |
| Модификатор характеристики | `floor((значение − 10) / 2)` |
| Бонус мастерства | по уровню: 1–4 → +2, 5–8 → +3, 9–12 → +4, 13–16 → +5, 17–20 → +6 |
| Спасбросок / навык с владением | модификатор + бонус мастерства |
| Навык с компетентностью | модификатор + 2 × бонус мастерства |
| Пассивное восприятие | 10 + бонус Внимательности |
| Инициатива | модификатор Ловкости + прочий бонус |

Бонус мастерства можно задать вручную (галочка на листе) — для домашних правил.

Лист хранится **на сервере** и синхронизируется:

* игрок видит и редактирует только свой лист и не может получить чужой
  (проверяется на сервере);
* во вкладке «Лист» у ДМ сначала открывается **список игроков**: нажатие на имя
  открывает лист этого игрока **в режиме просмотра**, кнопка «← К списку
  игроков» возвращает обратно. Пока никто не подключился, там написано «В лобби
  сейчас никого нет». Тот же лист можно открыть кнопкой «Открыть лист» в списке
  участников слева; открытый лист обновляется на лету при правках игрока.
* кнопка **«⧉ Отдельным окном»** выносит лист в отдельное окно приложения: его
  можно отодвинуть на второй монитор и работать с листом, не занимая панель
  стола. Игрок открывает так свой лист (и может в нём править), ДМ — лист
  выбранного игрока (только просмотр). Окно подключается к тому же столу тем же
  персонажем, поэтому правки видны и в основном окне, и здесь. В тренировочном
  столе (без сервера) окно работает так же, но берёт лист из общей заготовки
  листа, а не со стола. После выноса листа панель стола сворачивается до иконок.

## Карты, сетка, фишки, рисование карт, кубики, чат

* **Три вкладки карт**: «Общая карта», «Карта локации / битвы» и «Рисунок».
  **Во вкладке можно держать несколько карт** — ДМ загружает сколько нужно и
  переключается между ними стрелками «◀ ▶» или списком; прежние карты никуда не
  пропадают. Игрокам показывается выбранная карта той вкладки, для которой горит
  зелёная точка; вкладки позволяют заглянуть во вторую — с пометкой, что ДМ
  показывает другую. Удаляется только та карта, которую выбрал ДМ.
* **Приближение карты** — у каждого своё. Кнопки «−», «+» и «⤢ Сбросить» в углу
  карты, колесо мыши (приближает к точке под курсором) и перетаскивание карты
  мышью. Карта, сетка и фишки увеличиваются вместе, как если бы вы наклонились
  к столу: размер клетки и фишек относительно карты не меняется, а на других
  участников ваше приближение не влияет.
* **Туман войны**. Мастер может закрыть карту и открывать её по мере игры:
  кнопка «Туман: выключен» в панели карты включает режим кисти, ползунок задаёт
  её размер, а кнопки «Открыть всё» и «Закрыть всё» управляют картой целиком.
  Пока кисть включена, указатель открывает карту, а не двигает фишки; выключите
  режим, чтобы вернуться к обычной работе. Открытое видят все участники, причём
  у мастера туман бледный: он видит, где ещё темно, игроки видят почти сплошную
  темноту. Туман лежит поверх карты и фишек, поэтому закрытый участок не
  просвечивает. У каждой карты своя маска, она хранится в кампании и
  переживает перезапуск и переключение вкладок; карта, на которой ещё ничего не
  открыто, рисуется как обычно, без тёмного слоя. Кнопки тумана есть только у
  мастера, игрок управлять ими не может. Туман не печатается вместе с листом.
* **Освещение**. У карты есть своя вкладка «Свет» рядом с вкладками карт.
  Карта под ней остаётся видна: темноту и огонь нельзя настраивать вслепую.
  Ползунок задаёт темноту: ноль это дневной свет, сто это кромешная тьма, и
  карта без темноты не выглядит пожелтевшей. Рядом выбор источника и ползунок
  дальности, с названием и числом: «20 фт» и «40 фт» без подписи не отличить.
  Готовые источники взяты из правил и различаются оттенком: факел на 20 футов и
  тёплый, фонарь на 30, костёр на 40, свеча на 5, фонарь в капюшоне на 10,
  лунный свет на 60 и холодный, свет звёзд на 80, свет фонаря на клинке на 25,
  болотный огонь, волшебный, красный и дневной свет. Кнопка «Поставить свет»
  включает режим, клик по карте ставит источник, и он сразу попадает в список,
  где его можно погасить и зажечь снова, сделать тусклым или ярким и убрать
  крестиком.
* **Сам источник на карте не виден**. Точки в его месте нет ни у кого: видно
  только пятно света, а само место и дальность написаны в списке на вкладке.
  Именно поэтому список и нужен: погасить костёр, не находя его взглядом.
* **Стены, которые держат свет**. Кнопка «Рисовать стены» включает режим, в
  котором протяжка мышью рисует стену. За стеной образуется тень: свет упирается
  в неё и не проходит, а с другой стороны доходит до полной дальности. Стену
  убирает правый клик по ней, все сразу — «Убрать все стены». Стены рисуются
  только мастеру и только пунктиром поверх карты: игрок не должен видеть, где
  мастер их поставил.
* **Свет мягкий, круглый и своего цвета.** Тень от стены не идёт идеально прямой
  линией от источника: край пятна размыт, и он одинаково мягкий на картах любого
  размера. Пятно круглое, а не ромб: раньше по окружности шло всего четыре луча, по
  одному на каждую сторону света, и свет без стен выходил квадратом, повёрнутым на
  45 градусов. Теперь лучей шестьдесят четыре, и край контура не отличить от круга.
* **У каждого источника свой цвет.** Свет рисуется не вырезанием пятен из темноты, а
  отдельным слоем поверх ночной завесы, поэтому оттенок доходит до карты: лунный
  свет холодный и синий, болотный огонь зеленоватый, волшебный сиреневый. В
  списке двенадцать источников: факел, фонарь, костёр, свеча, капюшон, луна,
  звёзды, свет на клинке, болотный огонь, волшебный, красный и дневной. Новый
  источник появляется тусклым, а не ярким: яркий свет видят все сразу, и заготовка
  перестаёт быть заготовкой.
* **Тусклый и яркий.** По правилам это разный свет, а не разная яркость: тусклый
  светит вдвое меньше и выедает темноту не до конца, в нём видно силуэты, но не
  детали. У каждого источника в списке есть переключатель. Правило живёт в модели
  света, а не в отрисовке: иначе тень от тусклого отличалась бы от тени яркого того
  же радиуса, а не стала бы ею вдвое короче.
* **Свет от фишек**. У фишки в списке есть выбор источника, как у мастерских
  огней: факел в руке персонажа едет вместе с ней и освещает путь. Фишка без
  света светит нулём, и это то же самое, что «не светит».
* **Масштаб карты**. В настройках стола, рядом с сеткой, есть «футов в клетке».
  По правилам 5e клетка равна пяти футам, и в этой мере задана дальность света:
  факел на двадцать футов это четыре клетки. Если карта сделана не по правилам,
  мастер ставит своё число. Пересчёт идёт через клетки, а не через пиксели
  картинки, поэтому свет остаётся круглым на карте любых пропорций.
* **Порядок слоёв карты**: карта и сетка, поверх них поверхность (кислота,
  огонь, вода), выше фишки, выше ночная завеса, выше пятна света, выше стены с
  источниками, а самым верхним идёт туман. Пятна смешиваются с завесой
  экранированием, поэтому оттенок источника виден на карте, а не остаётся внутри
  ночного тона. Так фишка в темноте видна, а пятно света при этом не высвечивает
  участок, который мастер считает закрытым туманом. Свет и стены в распечатку
  карты не попадают.
* **Сворачиваемые панели**: «◀ Участники» убирает левую панель совсем, «Панель ▸»
  сворачивает правую до иконок вкладок чата, кубиков, листа и фишек (клик по
  иконке разворачивает панель обратно). Выбор запоминается.
* **Панель вкладок сбоку или снизу**. В настройках стола выбирается, где стоит
  правая панель: справа от карты или под ней. Выбор переживает перезапуск, а
  разделитель тянет ту сторону, где панель лежит: вбок он меняет ширину, вниз
  высоту.
* **Список листов живёт в панели участников**. Игрок выбирается слева, где у
  каждого есть кнопка «Открыть лист», а вкладка «Лист» без выбранного игрока
  говорит, куда идти. Портрет мастера переехал туда же, над списком: листа у
  него нет, а портрет нужен рядом с именем и у бросков в чате.
* **Режим боя и ход по клеткам**. Переключатель «Бой» в строке карты включает ход
  по клеткам; включается он и сам при общем броске инициативы. В бою фишка
  выбирается нажатием, а не таскается мышью: от фишки до клетки под указателем
  идёт линия, клетка подсвечивается, а в середине линии написано расстояние —
  шаги, клетки и футы. По правилам 5e шаг по прямой стоит клетку, по диагонали —
  корень из двух. Нажатием на клетку фишка проходит её клетка за клеткой и встаёт
  туда; на сервер уходит одна позиция по окончании хода.
* **Поверхность карты**. Отдельная вкладка «Поверхность»: огонь, кислота, вода,
  лёд, яд, скользкость, дым и руины. Мастер выбирает состояние и ведёт кисть по
  карте — красятся клетки под кистью выбранной ширины, а фишки остаются поверх:
  это пол, а не то, что стоит на нём. Есть ластик и «Очистить карту». Рисует
  только мастер, видят все, поверхность переживает кампанию.
* **Сетка на карте**. Включается кнопкой «Сетка» в панели карты или галочкой в
  настройках. Клетка **ровно по размеру фишки**: фишка занимает клетку целиком,
  в обоих режимах и при любом увеличении.
   * **Подгонка под карту** — поле «клеток по ширине карты»: мастер пишет, сколько
     клеток укладывается по ширине (например, 43.5), и размер клетки считается от
     настоящей ширины подложки, **без округления**. Полклетки хватает, чтобы
     сетка легла на картинку вплотную: на 1600 пикселей при 37 клетках клетка
     равна 43.24 пикселя, и целое число клеток клало бы сетку с ошибкой в
     несколько пикселей на всю ширину. Значение 0 возвращает ручной режим.
   * **Ручной размер** — поле в пикселях с шагом 1 (по умолчанию 46 px).
   * **Сдвиг сетки** — два поля в пикселях по осям. У готовой карты клетки
     начинаются не обязательно с угла файла, и без сдвига наша сетка на них не
     ложится.

  Число клеток, сдвиг и футы в клетке хранятся в кампании и приходят всем
  участникам, поэтому сетка одинаковая у всех; считает её каждый сам от своей
  копии подложки, результат совпадает. Сетку и размер задаёт ДМ.
* **Рисование карты самому**. Кнопка «Нарисовать карту» (или «Рисовать поверх
  карты», если карта уже загружена) открывает холст: кисть, линия,
  прямоугольник, ластик, цвет и его палитра, толщина, отмена штриха, очистка,
  привязка начала и конца штриха к клеткам. Подложкой можно взять любую
  загруженную карту или файл — рисунок ляжет поверх неё (подложка не
  растягивается, размер холста всегда кратен клетке, поэтому линии ложатся
  ровно). На пустой вкладке холст сам берёт карту, показанную игрокам, чтобы не
  начинать с пустого листа. Кнопкой «Сделать картой» рисунок сохраняется в любую
  из трёх карт; ластик стирает только штрихи и не портит подложку.
* **Фишки**. ДМ создаёт фишки, задаёт имя, назначает игроку, загружает
  изображение, перемещает и удаляет любые фишки. Правый клик по фишке открывает
  меню: переименовать, изображение, назначить игроку, скрыть, удалить. Игрок
  перемещает только свою фишку и может загрузить для неё картинку. Координаты
  хранятся долями от размера карты (`x`, `y` от 0 до 1), поэтому у всех
  участников фишки стоят одинаково. Перетаскивание — мышью или пальцем
  (Pointer Events).
* **Прочность фишки**. Мастер задаёт её прямо при создании («Прочность: 12»),
  а урон наносит кнопками `-5` и `-1` в списке фишек или точным числом в поле.
  Под кружком на карте идёт полоса и «7/12»: за боком смотрят на карту, а не в
  правую колонку. Половина и меньше — жёлтая полоса, ноль — красная и серый
  кружок: монстр пал, но остаётся на месте, чтобы было видно, где он лежит.
  Прочность не уходит ниже нуля и выше максимума. Фишка без прочности — метка,
  и урон по ней сервер отвергает с объяснением. Правит прочность только мастер:
  игрок меняет своё здоровье в листе, а две правки одного числа за столом
  разошлись бы. Прочность сохраняется с кампанией.
  **Прочность монстров игрокам не показывается**: её мастер ведёт у себя. Игрокам
  видно, что монстр на поле есть и где он стоит, но не сколько он ещё держится.
  Исключение — фишки игроков: их прочность видно всем, потому что урон наносится
  открыто. Прячется это на сервере, а не в интерфейсе: иначе число утекло бы в
  снимок состояния, который игрок получает целиком.
* **Скрытие фишек**. Новая фишка появляется **скрытой от игроков**: мастер
  сначала расставляет её и проверяет расстановку, потом открывает. Скрытая
  фишка видна только мастеру и помечена пунктиром, чтобы её не спутать с
  готовой. Открыть и снова спрятать можно и по одной (правый клик по фишке или
  кнопка «Скрыта» / «Видна» в списке фишек), и разом кнопками «Показать все»
  и «Скрыть все». Скрытым фишкам никто из игроков не получает ни положения,
  ни картинки, ни переименований — и в списке участников у игрока не появляется
  отметки о фишке, которую он не должен знать.
* **Фишка из листа**. Кнопка «Вывести» есть в двух местах: у игрока в списке
  участников и в панели фишек, отдельным блоком «Вывести из листа». Обе
  делают одно и то же: мастер выводит фишку прямо из листа — с именем
  персонажа и аватаром игрока, на текущей вкладке карт, сразу назначенную
  ему. Повторно кнопка не появляется, пока фишка уже есть: одна фишка на
  человека. Когда фишки есть у всех, блок так и говорит и списка не держит.
  Фишка, выведенная из листа, **живёт аватаром**: игрок сменил портрет — фишка
  обновилась сама. Но стоит поставить ей картинку руками, и аватар её больше не
  трогает, чтобы не затереть то, что нарисовали специально.
* **Лист персонажа до стола**: на главном экране у игрока есть карточка
  «Создать лист персонажа». Отдельный экран, а не панель стола: подключаться к
  мастеру ради заполнения листа незачем. Всё, что введено, сразу сохраняется на
  этом компьютере, а при подключении лист выбирается из списка кнопкой «Взять на
  стол» и один раз уезжает мастеру. Листов может быть много, они переживают
  перезапуск окна, и их можно править или удалить. В библиотеке двадцать записей:
  это черновики, а не архив персонажей, и localStorage не резиновый.
* **Печать листа**. Кнопка «⎙ Печать» в шапке листа открывает системное окно печати, где выбирается «Сохранить как PDF». На бумагу уходит только сам лист: белым по белому, без тёмных фонов темы, без шапки стола и панелей, с A4-полями. Кнопки и аватар на распечатке не показываются, блоки внутри не рвутся между страницами. Печатать можно и из окна листа, и из панели стола.
* * **Ячейки заклинаний**. Девять ступеней, у каждой занято и всего: `− 1 из 4`. Число
  «всего» подставляется по классу и уровню для полных заклинателей (бард, жрец, друид,
  чародей, волшебник, по-русски и по-английски). У полузаклинателей и warlock своя
  арифметика и особые правила, поэтому там поле остаётся пустым и число вписывается руками:
  приложение своё не выдумывает. Потратить больше, чем есть, нельзя, кнопка гаснет. Кнопка
  «Восстановить все» это длинный отдых: на коротком ячейки не восстанавливаются. Блок
  спрятан, если ячеек нет, у воина девять пустых рядов выглядели бы как девять долгов.
* **Заметка мастера об игроке**. В списке участников у мастера есть кнопка
  «Заметка»: там то, что он знает, а игрок не знает, например «на самом деле подслушивает
  для гильдии». Заметка пишется на лету, без кнопки «Сохранить»: о таких вещах вспоминают
  через десять минут, и терять её из-за не нажатой кнопки обидно. Пока она не пустая, кнопка
  помечена золотом, а под строкой видна короткая подсказка. Игроки не получают заметку ни в
  списке участников, ни в снимке состояния, ни по событию: поле у всех, но у игроков пустое,
  иначе форма записи прыгала бы при каждой рассылке списка. Хранится заметка у записи игрока,
  а не в листе: лист игрок видит целиком. Едет вместе с кампанией.
* **Состояния фишки**. Тринадцать состояний 5e: слепой, глухой, ослеплён, испуган,
  схвачен, недееспособен, невидим, парализован, окаменел, отравлен, сбит с ног, опутан,
  оглушён. Задаёт их мастер: в строке фишки видны включённые по именам, а полный
  список раскрывается по клику. Состояния, в отличие от прочности, видны и игрокам,
  потому что по ним и ориентируются, кого можно бить. Под фишкой на карте появляются
  короткие подсказки, невидимая фишка гаснет. Сервер отбрасывает состояния, которых
  нет в правилах, и повторы: такие значения приходят из файла кампании и из сообщений.
  «Без сознания» в списке нет намеренно, это следствие нулевых хитов, оно и так видно.
Истощения тоже нет: у него уровни от одного до шести, а здесь переключатели.
* **Переименование фишки**. Три пути, одно окно правки: правый клик по фишке на
  карте, двойной клик по ней же и правый клик по строке в списке фишек. Меню
  фишки везде одно и то же: переименовать, скрыть или показать имя, скрыть или
  показать подписи, задать изображение, назначить игроку, скрыть или показать
  фишку, удалить.
* **Скрытое имя фишки**. Переключатель «Без имени» стоит в строке фишки и есть
  в меню. Фишка остаётся видимой, но подпись под ней и имя её игрока не
  рисуются, а в кружке вместо буквы стоит «?». Так выводят загадочного NPC или
  босса, имя которого игроки узнавать не должны. Мастер своё имя по-прежнему
  видит, а в списке строка помечена: у мастера вместо имени написано «Имя
  скрыто». Игрокам сервер отдаёт пустую строку с флагом, а не само имя: флаг
  «не показывать» спрятал бы подпись в интерфейсе, а имя осталось бы в снимке
  состояния и в каждом событии фишки.
* **Подписи без фишки**. Переключатель «Без подписей» стоит рядом с «Без имени»
  и есть в меню фишки. Под фишкой не рисуются ни имя, ни имя её игрока, ни
  подписи состояний, и убирается это у всех сразу, включая мастера: на тесной
  карте подписей больше, чем нужно, а секрета тут нет. Рисунок состояния на
  фишке остаётся, так что по карте всё равно видно, кого связало. Выбор едет
  вместе с кампанией.
* **Состояния меняют фишку**. У каждого состояния свой рисунок на карте: лоза
  снизу у «опутанного», камневая короста у «окаменевшего», молнии у
  «парализованного», звёзды над головой у «оглушённого», повязка у «слепого»,
  фишка ложится набок у «сбитого с ног». Пять состояний по правилам 5e отнимают
  скорость целиком: опутан, парализован, окаменел, оглушён и недееспособен.
  Пока они висят, игрок не может сдвинуть свою фишку, курсор говорит «нельзя»,
  а попытка объясняет названием состояния. Мастер при этом связанные фишки
  двигает: перетащить соперника можно и нужно. Сервер проверяет то же правило и
  отказывает, даже если игрок прислал движение напрямую, минуя карту.
* **Кубики**: настоящие кости — d4, d6, d8, d10, d12, d20 и d100 для
  процентных бросков. Раньше панель предлагала все двадцать, и половина
  вариантов в игре не встречается: костей на три, пять или семь граней не
  бывает. Панель умеет и формулы: `2d6+3`, `4d6dl1` (бросок характеристики,
  отбросить худшую кость), `2d20kh1` (преимущество), `2d20kl1` (помеха),
  `d100-1` (процент). Лишние пробелы и регистр не важны: `2 D6 + 3` — то же
  самое, что `2d6+3`. Формулу разбирает сервер, числа считает он же. Подсунуть
  серверу «несуществующую» кость нельзя даже сообщением: костей на три грани
  нет и в формуле тоже.
* **Тайный бросок**: мастер может бросить, не показывая игрокам числа. В чате
  появляется строка «бросил 2d6+3 тайно», в истории броска вместо числа стоит
  вопросительный знак, а само число остаётся только у мастера: ни в чате, ни в
  снимке состояния, который получает игрок, его нет. Игрок тайно бросить не
  может, его бросок видят все.
* **Проверка прямо из листа**. У каждой характеристики, каждого спасброска и
  каждого навыка есть кубик: нажатие бросает `d20` с модификатором из листа.
  Рядом с характеристиками стоит переключатель «обычно, преимущ., помеха», и он
  меняет саму формулу: `d20+3`, `2d20kh1+3` или `2d20kl1+3`. Переключатель один
  на весь лист, потому что за бой преимущество нужно почти всегда, а кнопки под
  каждой характеристикой превратили бы лист в список мелких кнопок. Модификатор
  берётся из листа в момент броска, а не из надписи: поправил характеристику,
  и следующий бросок уже с новым числом. Бросок уходит тем же кубиком, что и из
  панели: его видит весь стол, он попадает в историю и в чат. Из чужого листа у
  мастера бросать нельзя, из списка игроков бросков нет, на экране подготовки
  кубиков нет вовсе.
* **Спасброски смерти**. Когда хиты падают до нуля, в листе появляется блок с
  двумя счётчиками: успехи и неудачи. Кнопка «Бросить спасбросок» отправляет бросок
  на сервер, и считает он же: десятка и выше — успех, единица — сразу две неудачи,
  двадцатка поднимает персонажа с одного хита и обнуляет счётчики. Считать на клиенте
  нельзя, игрок подкрутил бы и число, и счётчик. Бросок уходит в общую ленту и в чат,
  его видят все. Счётчики можно двигать кнопками вручную, если их считают не броском,
  и обнулить кнопкой сброса, когда герой пришёл в себя: сам лечение их не трогает,
  три неудачи у живого персонажа выглядели бы как ошибка. Блок спрятан, пока хиты не
  нулевые. Три неудачи значат смерть, три успеха — стабилизацию, и счётчик дальше трёх
  не растёт. Бросает только сам игрок за свой лист.
* **Переброс**: кнопка повторяет последний бросок, не нужно заново набирать
  формулу.
* **Порядок боя** (вкладка «Бой»): кто за кем ходит. Список ведёт мастер, видят
  его все, потому что «кто ходит» и есть объявление для игроков. Мастер
  добавляет игроков одной кнопкой, модификатор каждого подставляется из его
  листа (Ловкость плюс прочий бонус), фишки выбираются из списка на карте, а
  того, чего на столе нет, добавляют под своим именем. «Бросить» кидает d20
  каждому и пересобирает порядок: больше итог, значит раньше; при равенстве
  больше модификатор. Клик по строке объявляет чей ход, «Следующий» листает
  порядок и на переходе с последнего на первого считает новый раунд. Игрок
  видит тот же список и не может им управлять: все действия проверяет сервер.
  Удалённая с карты фишка исчезает из порядка боя вместе с собой, а сам бой
  переживает переподключение и сохраняется с кампанией.
* **Бросок выполняет сервер**, результат рассылается всем вместе с именем и
  временем. Отброшенные кости видны в строке броска: «4d6dl1: 14 (отброшено
  2)», иначе такой итог выглядит как ошибка сложения. История бросков хранится
  за сессию и попадает в кампанию.
* **Поиск по чату**. Поле над лентой ищет и по тексту сообщения, и по имени
  автора: за столом вопрос звучит как «что говорил Мастер про ловушки», и начинать
  надо с имени. Найденные строки подсвечиваются, ненайденные приглушаются, а
  счётчик показывает, сколько нашлось. Остальные не скрываются: правило ищут в
  контексте разговора. Поиск переживает переподключение и новые сообщения, Escape
  его сбрасывает.
* **Чат**: общий, с именем автора и временем. У броска кубика перед именем
  стоит портрет бросившего — так сразу видно, чей это результат. Портрет
  пишется в само сообщение, поэтому в истории остаётся тот, каким был в момент
  броска. История за сессию; последние сообщения сохраняются с кампанией.
* **Список игроков**: портрет (или буква имени, если портрета нет), имя, роль
  (ДМ / игрок), статус в сети, у ДМ — кнопки «Фишка на поле» и «Открыть лист».
* **Аватар**. Игрок ставит портрет в своём листе, в блоке «Персонаж»:
  PNG, JPG или WEBP до 2 МБ. Портрет виден всему столу — в списке участников и
  у бросков в чате, — но это картинка, а не данные листа, поэтому чужие
  характеристики она не раскрывает. Меняет аватар только сам игрок, даже мастер
  в чужом листе кнопку не видит. У мастера, пока он не поставил свой, есть
  портрет из поставки: мудрый старец-архимаг. Свой портрет мастер меняет
  в списке игроков, блок «Ваш портрет»: своего листа персонажа у него нет,
  поэтому портрет живёт именно там.
* **Настройки** (кнопка «⚙ Настройки» на главном экране и на столе): версия,
  режим, папка данных, **оформление**, язык интерфейса, а за столом у ДМ —
  сетка и размер клетки.
  Вне стола здесь же лежит запуск стола без сервера (см. «Стол без сети»).
  Панель «Адреса для подключения» сворачивается кнопкой «Скрыть», в свёрнутом
  виде показывает основной адрес.

## Правая колонка

Колонка с чатом, кубиками, листом, фишками, боем и справочником приключения —
самое часто правящееся место за столом, поэтому её можно настроить под себя.

* **Ширина тяется мышью.** Между картой и колонкой стоит разделитель: тяните его,
  а ширина запоминается и переживает перезапуск. Разделитель двигается и
  стрелками, если мыши под рукой нет. Пока разделитель не трогали, ширина
  задаётся сама и сужается вместе с окном; своё значение вы задаёте первым же
  перетаскиванием. Сворачивание колонки до иконок выбранную ширину не сбрасывает.
* **Вкладки переключаются цифрами.** На экране стола `1`..`9` открывают вкладки
  по порядку, а `Ctrl+F` открывает чат и ставит фокус в поиск по ленте. В поле
  ввода цифра остаётся цифрой: «2» в формуле броска не переключит вкладку.
* **Последняя вкладка запоминается.** Закрыли окно, открыли — открыта та, что
  была в прошлый раз.
* **Длинные списки сворачиваются.** «Вывести из листа», «Все фишки» и «История
  бросков» живут в секциях с треугольником. Свёрнутое состояние переживает
  перерисовку панели и перезапуск, а развернутая лента бросков докручивается
  до конца сама.
* **Фишки ищутся и фильтруются.** Когда фишек больше трёх, у мастера над
  списком появляется поле поиска по имени и переключатели «Все», «Скрытые»,
  «С моим именем», «Без имени». Когда ничего не нашлось, панель говорит, что
  показано 0 из скольких: пустой список рядом с полем поиска выглядил бы так,
  будто фишек нет вовсе.

## Темы оформления

Пять палитр, переключаются в «Настройках» → «Оформление» и применяются сразу,
без перезапуска:

| Тема | Вид |
|---|---|
| **Стандартная** | та, что была до тем: тёплый коричневый и охра |
| **Лес** | холодная зелень, тёмная хвоя, светлый мох |
| **Магия** | чернильный фиолетовый, светящаяся лоза |
| **Океан** | глубокая вода, холодный свет, пена |
| **Трактир** | тёплое дерево, охра и свечной свет |

Каждая тема переопределяет один и тот же набор переменных (`--bg`, `--surface`,
`--border`, `--text`, `--accent`, `--gold`, `--danger`, `--ok`, `--info`), поэтому
разметка не меняется. Чтобы добавить тему, достаточно описать эти поля в
`renderer/styles/01-tokens.css` и дописать строку в список `THEMES` в
`renderer/theme.js`.

### Смысловые цвета

Опасные кнопки, бейджи ролей, полоска прочности фишки, отметка «показана игрокам»,
признак экспертизы, затемнение под модальным окном и стена на карте раньше красились
числами прямо в правилах, поэтому во всех пяти темах выглядели одинаково: тема
меняла панели, а смысловые вещи оставались прежними.

Теперь это роли в палитре: `--danger-text`, `--danger-bright`, `--danger-soft`,
`--danger-border`, `--ok-text`, `--ok-soft`, `--ok-border`, `--info-text`,
`--info-soft`, `--info-border`, `--hp-plate`, `--hp-track`, `--hp-track-soft`,
`--off`, `--dot-idle`, `--expertise`, `--expertise-soft`, `--scrim`,
`--disabled-bg`, `--hover-wash`, `--shadow-press`, `--wall`. Мягкий вариант
считается из базового цвета через `color-mix`, поэтому каждая тема получает свои
значения сама, а не из пяти рукописных наборов, и новая тема не потребует их
заполнять. Единственное, что выбирается руками, это оттенок роли игрока `--info`:
он содержателен и из акцента не выводится.

### Кольцо фокуса

Запасной вариант задан один на весь интерфейс в `01-tokens.css` и стоит раньше
частных правил, поэтому кнопки и поля с собственным оформлением фокуса остались как
были, а элементы без своего правила перестали быть слепыми: по ним раньше не было
видно, где клавиатурный курсор. Раньше фокус был описан в четырёх местах и четырьмя
способами, а кнопка и разделитель панелей выглядели при этом частью разных миров.

### Оформление разбито на восемь файлов

`renderer/styles.css` на 5409 строк пришлось делить. Части идут по порядку номеров
и подключаются в том же порядке: CSS зависит от порядка правил одинаковой
специфичности, и перестановка молча изменила бы вид.

| Файл | Что внутри |
|---|---|
| `01-tokens.css` | Палитра, смысловые цвета, живой слой тем, кольцо фокуса |
| `02-screens.css` | Главный экран, вход в стол, подключение, модальные окна |
| `03-controls.css` | Кнопки, поля, списки, бейджи, топбар |
| `04-layout.css` | Раскладка экрана, сворачиваемые панели, вкладки, участники |
| `05-map.css` | Подложка карты, вкладки карт, сетка, приближение, фишки на карте |
| `06-panels.css` | Фишки, вывод из листа, чат, кубики, порядок боя |
| `07-sheet.css` | Лист персонажа, настройки стола, импорт и справочник приключения |
| `08-theme-layer.css` | Анимации по темам, атмосфера, переделки элементов, печать |

Файл правится целиком, читается по части. `test/styles.js` Проверяет и порядок
частей, и то, что вне палитр не осталось голых цветов, и что каждая роль
объявлена и используется: именно эта проверка не даст вернуть зашитые цвета
обратно.

### Общий слой оформления

Кроме цвета, у всех тем есть общий «настольный» слой: он задаётся общими
переменными и одинаково работает в каждой палитре.

* **Гравировка.** У панелей светлая кромка сверху и тень снизу, у кнопок —
  блик по верхней грани. Плоские заливки выглядели бы как цветные прямоугольники,
  а не как вырезанные из камня детали.
* **Шрифты.** Заголовки — дисплейный шрифт с разрядкой, подписи панелей —
  капитель, числа (кубики, модификаторы, характеристики) — табличные, чтобы
  цифры не прыгали при изменении.
* **Орнамент.** Логотип — гранёная пластина с ромбом, пустая карта помечена
  водяным знаком гранёного куба, заголовки панелей подчёркнуты волосяной линией.
* **Движение.** Экраны и панели проявляются, карточки главного экрана
  поднимаются по очереди, строки чата и списков въезжают сбоку, бросок кубика
  выскакивает и расходится кольцом, тосты и модальные окна расплываются, а
  блеск пробегает по карточке при наведении.
* **Фактура.** Поверх всего — едва заметное зерно: интерфейс выглядит скорее
  напечатанным, чем нарисованным.

### Чем темы отличаются помимо цвета

* **Рамки.** Своя толщина и начертание (`--frame`), своя внутренняя обводка,
  своё скругление: у «Трактира» углы почти прямые и рамка вдвое толще, у «Океана»
  панели сильно скруглены, у «Магии» двойная обводка и светящиеся уголки, у
  «Леса» скругление неровное, как у листа. Панели и карточки на главном экране
  рисуют уголки линиями цвета темы.
* **Анимации.** Подложка-атмосфера под всем содержимым: в «Лесу» ползут пятна
  солнца, в «Магии» проступают искры, в «Океане» идёт волна, в «Трактире» дрожит
  неровный свет свечей. Заголовки дышат в такт теме.
* **Шрифты.** Заголовочная гарнитура одна на все темы: тонкая антиква Cormorant,
  набранная как надпись на старинной книге. Тема меняет её характер — начертание,
  разрядку и насыщенность: «Магия» тонкая и просторная, «Трактир» плотный и весомый,
  «Океан» светлый, «Лес» сдержанный. Раньше у каждой темы был свой шрифт, и часть
  из них (Rockwell, Bahnschrift) кириллицы не содержит: русские заголовки молча уходили
  в подстановочный шрифт, и заголовок выглядел сломанным. Теперь русский набирается
  той же гарнитурой, что и латиница.
  Основной текст — системный Segoe UI: он спокойный, разборчивый и не тяжелит сборку.
  Заголовочный шрифт лежит рядом с интерфейсом (`renderer/fonts`), а не тянется из сети:
  игра работает офлайн. Подмножества разделены по файлам, кириллица весит отдельно.

Анимируется только `transform` и `opacity`, поэтому карта с кучей фишек не
просядет. То же и с расчётом координат: у фишек не двигается `transform`, иначе
прыжок броска сбился бы. Системная настройка «уменьшить движение» отключает
анимации, оформление остаётся. Темы связаны только переменными: разметка и
поведение у всех тем одни и те же.

Тема — дело каждого: она хранится в настройках этого компьютера, а не в кампании,
поэтому игроки видят стол в своей палитре. Выбор применяется до первой отрисовки
(скрипт подключён раньше стилей) и расходится на окно листа персонажа.

### Шрифты

Заголовочный шрифт — **Cormorant** (Christian Thalmann, SIL Open Font License 1.1),
  он лежит в `renderer/fonts` вместе с лицензией `OFL.txt`. Файлы разделены по
  подмножествам: браузер подгружает только нужное, кириллица не тащится вместе с
  латиницей. Обновляется скриптом:

```bash
node scripts/fetch-fonts.js
```

Без интернета игра работает как обычно: шрифт уже лежит рядом с интерфейсом.

### Как посмотреть на оформление

`scripts/make-shots.js` Снимает главный экран, стол, лист и экран подключения
в каждой теме:

```bash
npx electron scripts/make-shots.js [папка]
```

Снимки складываются в `shots/` (в репозитории их нет). Нужен, чтобы оценить
оформление глазами: правила CSS ничего не говорят о том, как это выглядит.

`deleteToken {tokenId}`, `rollDice {sides}`, `chatMessage {text}`.

Освещение карты: `setMapDarkness {type, mapId, darkness}`,
`addMapWall {type, mapId, wallId, x1, y1, x2, y2}`,
`deleteMapWall {type, mapId, wallId}`, `clearMapWalls {type, mapId}`,
`addMapLight {type, mapId, lightId, x, y, radius, color}`,
`setMapLight {type, mapId, lightId, radius?, color?, hidden?}`,
`deleteMapLight {type, mapId, lightId}`, `setTokenLight {tokenId, radius, color}`.
Идентификаторы стены и источника даёт клиент: мастер рисует и сразу видит
результат, а выданный сервером второй экземпляр остался бы висеть навсегда.
`setGrid` принимает ещё `feetPerCell`.

`server → client`:
`joined {you, state}`, `playersUpdate […]`, `characterSheetData {playerId, sheet}`,
`characterSheetUpdated {playerId, sheet}`,
`mapUpdated {type, items, activeId, activeMap}`,
`gridUpdated {enabled, cell}`,
`tokenCreated token`, `tokenUpdated token`, `tokenMoved {tokenId, x, y}`,
`tokenDeleted {tokenId}`, `diceRollResult {playerId, playerName, sides, result, time}`,
`chatMessage {from, role, text, time, isRoll?}`, `errorMessage {message}`.

Дополнительно: `joined` (полный снимок состояния при входе) и `renameToken`
(переименование фишки ДМом). Тип карты `type` — один из `world` (общая),
`battle` (локация) и `sketch` (рисунок ДМа); `items` — карты этой вкладки в
порядке загрузки, `activeId` — какую из них показывать.
`uploadMap` добавляет карту к уже загруженным в вкладке, а не заменяет прежние.

## Безопасность

* `contextIsolation: true`, `nodeIntegration: false`; renderer видит только то,
  что перечислено в `preload.js`.
* Роль ДМ проверяется на сервере (loopback + `hostKey`).
* Сервер стола слушает только `127.0.0.1`: из локальной сети и из интернета на
  него нельзя попасть в принципе, а к туннелю iroh допускается только тот, у
  кого есть билет мастера.
* Игрок не может получить чужой лист, двигать или удалить чужую фишку,
  управлять картами и кампаниями — это проверяется на сервере, а не только
  скрытием кнопок в интерфейсе.
* Имя и сообщения обрезаются по длине, пустые отклоняются; изображения —
  по типу (включая сигнатуру) и размеру.
* CSP в `index.html` ограничивает источники скриптов и стилей.
* Файлы картинок (`GET /files/:name`) отдаются с заголовком
  `Access-Control-Allow-Origin: *` — иначе renderer не смог бы положить
  загруженную карту на холст для рисования (браузер считает такой холст
  «загрязнённым»). Доступны только файлы текущей кампании из папки `files`.

### Известное ограничение

У игрока нет пароля: привязка к прежнему листу персонажа идёт по локальному
`playerId`, который сообщает клиент (так требует сценарий переподключения).
Чтобы выдать себя за другого, злоумышленнику нужно знать чужой UUID — то есть
получить доступ к компьютеру игрока. Билет мастера — единственный барьер на
входе, поэтому передавайте его только тем, кто реально за столом.
